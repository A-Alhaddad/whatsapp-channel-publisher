# مرجع API — WhatsApp Channel Publisher

واجهة HTTP داخلية للباك إند. العنوان الافتراضي `http://127.0.0.1:3187`. كل المسارات، بما فيها حالة الاتصال، تحتاج:

```http
Authorization: Bearer <PUBLISHER_TOKEN>
Accept: application/json
```

لطلب النشر أضف `Content-Type: application/json`. لا ترسل `Origin`؛ الخدمة ترفض الطلبات القادمة مباشرة من المتصفح. مرّر طلبات لوحة التحكم عبر الباك إند بعد التحقق من صلاحيات المسؤول.

## المسارات

| الطريقة والمسار | الوظيفة | الاستجابة المعتادة |
| --- | --- | --- |
| `GET /session` | حالة الحساب ورمز الربط الحالي | `200` |
| `POST /session/start` | بدء الربط أو الاتصال | `202` |
| `GET /channels` | القنوات التي يملك الحساب صلاحية النشر فيها | `200` |
| `POST /publications` | إنشاء محاولة نشر أو استرجاع محاولة موجودة بنفس المفتاح والمحتوى | `202` أو `200` |
| `GET /publications/{key}` | قراءة نتيجة محاولة واحدة | `200` أو `404` |
| `POST /publications/{key}/retire` | إغلاق محاولة غير مؤكدة أو غير موجودة ومنع وصول طلبها المتأخر | `200` أو `409` |

### حالة الحساب

```json
{
  "state": "ready",
  "qr": null,
  "account": "COUNTRY_CODE_AND_PHONE"
}
```

افحص `state === "ready"` قبل إتاحة النشر. أثناء الربط قد توجد قيمة `qr` بصيغة `data:image/png;base64,...`؛ اعرضها للمسؤول فقط، ولا تسجلها في logs. رمز QR مؤقت. `POST /session/start` يبدأ عملية غير متزامنة؛ تابع `GET /session` لمعرفة النتيجة.

### القنوات

```json
{
  "channels": [
    {"id": "123456789@newsletter", "name": "اسم القناة"}
  ]
}
```

القنوات الفارغة مدعومة. الحساب يجب أن يكون مالكًا أو مسؤولًا لديه صلاحية النشر؛ متابعة القناة وحدها لا تكفي. يرجع المسار `409 not_connected` إذا لم يكتمل الربط.

### إنشاء منشور

```json
{
  "key": "970a10ae-1c6f-4af8-b987-179656e4c807",
  "target": "123456789@newsletter",
  "text": "عنوان المنشور\nتفاصيله\nhttps://example.com/item/123",
  "image": {
    "mime": "image/jpeg",
    "data": "<BASE64_OF_IMAGE_BYTES>"
  }
}
```

| الحقل | الشروط |
| --- | --- |
| `key` | UUID جديد لكل محاولة مقصودة. أنشئه واحفظه في مشروعك قبل HTTP POST. استخدم UUID بحروف صغيرة. |
| `target` | معرّف قناة من قائمة القنوات: أرقام يتبعها `@newsletter`. لا يقبل المجموعات أو جهات الاتصال أو روابط الدعوة. |
| `text` | نص غير فارغ، بحد أقصى 3000 وحدة UTF-16 كما يحسبها JavaScript `text.length`؛ بعض الرموز التعبيرية تحسب وحدتين. |
| `image` | اختياري، ويمكن حذفه أو إرسال `null`. صورة واحدة في المنشور. |
| `image.mime` | `image/jpeg` أو `image/png` أو `image/webp`. |
| `image.data` | Base64 لبايتات الصورة، دون بادئة `data:...`. حجم الصورة قبل Base64 لا يتجاوز 10 MiB. يتم فحص توقيع نوع الصورة. |

الحد الإجمالي لطلب JSON هو 15 MiB. لا تقبل هذه النسخة فيديو أو ألبوم صور. إذا كان إعلان مشروعك يحتوي صورًا متعددة، يختار المستخدم صورة واحدة ويجهزها الباك إند. روابط الصور لا تُحمّل بواسطة الخدمة.

### نتيجة النشر

مثال لاستجابة بداية المعالجة `202`:

```json
{
  "key": "970a10ae-1c6f-4af8-b987-179656e4c807",
  "target": "123456789@newsletter",
  "hash": "<PAYLOAD_SHA256>",
  "status": "pending",
  "updated_at": "2026-01-01T10:00:00.000Z"
}
```

تابع `GET /publications/{key}`. عند تأكيد النشر تصبح `status: "sent"` وتضاف `message_id` و`sent_at`. جميع الأوقات في سجل الخدمة ISO 8601 بتوقيت UTC؛ توقيت النص المنشور تحدده أنت عند صياغته.

| الحالة | معناها والتصرف الصحيح |
| --- | --- |
| `pending` | المحاولة قيد المعالجة. تابع الحالة؛ لا تبدأ نسخة جديدة. |
| `sent` | وصل تأكيد إرسال. احفظ المعرّف والوقت في مشروعك. |
| `rejected` | فحص صلاحية القناة رفض النشر قبل الإرسال. أصلح صلاحية الحساب ثم يمكنك إعادة نفس الطلب بنفس المفتاح والمحتوى. |
| `unknown` | نتيجة الإرسال غير مؤكدة. قد يكون المنشور وصل. راجع القناة يدويًا؛ لا تعاود الإرسال تلقائيًا. |
| `retired` | المحاولة مغلقة؛ لن يُرسل أي طلب لاحق بهذا المفتاح. لا تعني أن منشورًا سابقًا حُذف. |

الخدمة تحتفظ بالمفتاح وبصمة المحتوى والحالة، ولا تحتفظ بالنص أو بايتات الصورة في سجل الإيصالات.

### تكرار الطلب وانقطاع الاتصال

- نفس المفتاح ونفس المحتوى يعيدان السجل الموجود دون نشر جديد، عدا حالة `rejected` التي تسمح بإعادة فحص الصلاحية.
- تغيير النص أو القناة أو الصورة مع نفس المفتاح يعطي `409 payload_changed`.
- إذا انقطع HTTP أو انتهت المهلة، اقرأ نتيجة **المفتاح نفسه**. عملاء الحزمة لا يعيدون POST تلقائيًا.
- `404` لا يثبت وحده أن الطلب السابق لن يصل؛ قد يكون تحميله متأخرًا. بعد فحص القناة، يمكن استدعاء `POST /publications/{key}/retire` لإغلاق المفتاح قبل اتخاذ قرار بمحاولة جديدة.
- الإغلاق مسموح فقط للسجل `unknown` أو `retired` أو مفتاح غير موجود. `pending` و`sent` و`rejected` تعطي `409 attempt_active`.
- بعد إغلاق محاولة غير مؤكدة، راجع القناة مرة أخرى وحدد إن كان هناك داعٍ للنشر. الإغلاق لا يلغي منشورًا وصل بالفعل.
- عند إعادة تشغيل الخدمة تتحول المحاولات `pending` إلى `unknown`؛ لا تُستأنف تلقائيًا.
- لإعادة نشر مقصودة بعد نتيجة `sent`، اطلب تأكيدًا من المستخدم، وأنشئ محاولة جديدة بمفتاح جديد، واحتفظ بسجل المحاولة السابقة.

هناك عملية إرسال واحدة نشطة في كل لحظة لكل نسخة خدمة؛ الطلبات الأخرى ترجع `409 busy`. على المشروع تنظيم طابور الطلبات.

## الأخطاء

شكل الخطأ: `{"code":"unauthorized"}`. لا تعتمد على رسالة نصية مترجمة.

| HTTP | code | التفسير |
| --- | --- | --- |
| 401 | `unauthorized` | المفتاح مفقود أو غير صحيح. |
| 403 | `origin_forbidden` | الطلب يحتوي Origin؛ استخدم الباك إند. |
| 404 | `not_found` | مسار أو محاولة غير موجودة. |
| 409 | `not_connected` | الحساب غير جاهز. |
| 409 | `busy` | توجد محاولة إرسال نشطة. |
| 409 | `payload_changed` | المفتاح مستخدم بمحتوى مختلف. |
| 409 | `attempt_retired` | المفتاح مغلق. |
| 409 | `attempt_active` | حالة المحاولة لا تسمح بإغلاقها. |
| 415 | `json_required` | نوع المحتوى ليس JSON. |
| 422 | `invalid_payload` | خطأ في الحقول أو نوع/حجم الصورة. |
| 422 | `channel_not_writable` | الحساب لا يستطيع النشر في القناة. |
| 400 / 413 | `service_unavailable` | JSON غير صالح / جسم الطلب أكبر من الحد. |
| 503 | `service_unavailable` | تعذر إكمال العملية؛ اقرأ سجل المحاولة قبل أي إعادة إرسال. |

عملاء PHP وNode.js يضيفون أخطاء محلية مثل `transport_error` و`invalid_response` و`loopback_url_required` و`private_token_required` و`invalid_key`. خطأ النقل أثناء النشر لا يعني أن المنشور لم يصل.
