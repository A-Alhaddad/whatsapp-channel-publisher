# النشر على Linux

شغّل الخدمة بجانب باك إند الموقع باستخدام مستخدم عادي، وNode.js إصدار 22.12 أو أحدث، وChrome/Chromium يعمل على السيرفر. الخدمة تستمع على `127.0.0.1` فقط؛ لا تعرض منفذها للعامة.

## إعداد systemd

القالب موجود في [deploy/whatsapp-channel-publisher.service](../../deploy/whatsapp-channel-publisher.service). جهّز التالي قبل تشغيله:

| الإعداد | القيمة المقترحة |
| --- | --- |
| المستخدم والمجموعة | `whatsapp-publisher` |
| مجلد العمل | `/opt/whatsapp-channel-publisher` |
| ملف الإعدادات | `/etc/whatsapp-channel-publisher.env` |
| البيانات الدائمة | `/var/lib/whatsapp-channel-publisher` |
| مسار Node | `/usr/bin/node` مع التحقق من المسار الفعلي |

ثبّت الاعتماديات باستخدام `npm ci --ignore-scripts`. أنشئ مفتاحًا خاصًا جديدًا عبر `npm run setup`، ثم ضع الإعدادات في ملف البيئة. اضبط `PUBLISHER_DATA_DIR` على مسار البيانات الدائم و`CHROME_EXECUTABLE_PATH` على المتصفح المثبت. اجعل صلاحية ملف الإعدادات `600`، ومجلد البيانات `700` ومملوكًا لمستخدم الخدمة.

ثبّت الوحدة في `/etc/systemd/system/` ثم:

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now whatsapp-channel-publisher
sudo systemctl status whatsapp-channel-publisher
```

قالب systemd يقرأ `/etc/whatsapp-channel-publisher.env`، بينما أوامر `npm run cli` تقرأ `.env` من مجلد المشروع. شغّل CLI بمستخدم الخدمة وبنفس الإعدادات، أو جهّز له `.env` خاصًا بالقيم نفسها. لا تشغّل عمليتين على نفس مجلد البيانات.

## المتصفح والربط

ثبّت متطلبات المتصفح من حزم نظام التشغيل. شغّله بمستخدم عادي؛ لا تعطّل sandbox لمعالجة مشكلة تشغيله بحساب root. اتبع خطوات QR في دليل التشغيل، وانقل صفحة الربط بشكل خاص إلى جهازك إذا كانت الخدمة على سيرفر بعيد.

احتفظ بمجلد البيانات ونسخة احتياطية خاصة منه؛ فهو يحتوي على جلسة الربط وسجل المحاولات. حذف السجل يفقد القدرة على اكتشاف مفاتيح محاولات نُشرت سابقًا.

## التحديثات

راجع التغييرات وحالة ملفاتك قبل التحديث. أوقف الخدمة لتحديث منظم، واحتفظ بملف الإعدادات والبيانات الخاصة، وثبّت الاعتماديات المحددة وشغّل الاختبارات ثم أعد التشغيل. تحقّق من `/session` وراجع المحاولات غير المحسومة. تتحول `pending` إلى `unknown` بعد إعادة التشغيل، ولا يعاد إرسالها تلقائيًا.

لكل نسخة مستقلة استخدم مفتاحًا ومنفذًا ومجلد بيانات مختلفين. إذا كان الموقع على سيرفر آخر، يمكن استخدام نفق خاص إلى المنفذ المحلي. الحزمة لا تتضمن صورة Docker؛ تشغيلها داخل حاوية يحتاج إعداد شبكة ومتصفح مناسبين.
