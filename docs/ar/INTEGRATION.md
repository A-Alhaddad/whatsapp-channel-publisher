# دمج الخدمة في مشروع آخر

الخدمة لا تعرف المستخدمين أو الإعلانات أو الأسعار أو قواعد موقعك. الباك إند يقرر من يحق له النشر، ويجهز النص والصورة، ثم يرسل طلبًا واحدًا للخدمة.

## شاشة الإعدادات

1. احصر الوصول بالمسؤولين في مشروعك، مع حماية CSRF لطلبات المتصفح.
2. زر «بدء الربط» يستدعي باك إند مشروعك، الذي يستدعي `POST /session/start`.
3. تابع `GET /session` واعرض `qr` في شاشة المسؤول. أوقف تحديث QR عند `ready`.
4. اعرض نتيجة `GET /channels` في قائمة القنوات. خزّن معرّف القناة المختارة في إعدادات مشروعك.
5. احتفظ بالمفتاح داخل إعدادات السيرفر؛ لا ترسله إلى المتصفح.

## شاشة النشر

- اقرأ العنصر من قاعدة بيانات مشروعك وتحقق من صلاحية نشره.
- اعرض معاينة النص وصور العنصر؛ تحقّق في الباك إند أن الصورة المختارة تتبع لهذا العنصر.
- جهّز النص بالقواعد المناسبة للمشروع، مثل نوع الإعلان والأسعار ووقت النهاية والمدينة وتكلفة التوصيل. تنسيق النص وتوقيت عرضه مسؤولية المشروع.
- حمّل الصورة من تخزينك الموثوق وتحقق من الحجم والنوع، ثم حوّل بايتاتها إلى Base64. لا تمرر رابطًا عشوائيًا من المتصفح إلى أداة تحميل غير مقيدة.
- عند ضغط «نشر»، أنشئ UUID واحفظ المحتوى النهائي والصورة المختارة قبل إرسال POST.
- تابع نتيجة نفس UUID وأظهر «تم النشر» فقط بعد `sent`.

## سجل مقترح في قاعدة بيانات مشروعك

| الحقل | الغرض |
| --- | --- |
| `publication_key` | UUID فريد، مع قيد unique |
| `item_id` | العنصر أو الإعلان داخل مشروعك |
| `channel_id` | القناة المستخدمة وقت المحاولة |
| `payload_snapshot` | المحتوى النهائي الثابت للمحاولة، في تخزين خاص |
| `image_id` | الصورة التي اختارها المسؤول إن وجدت |
| `status` | الحالة المحلية وحالة الخدمة |
| `message_id` | معرّف الرسالة المؤكدة |
| `sent_at` | وقت النشر المؤكد |
| `created_by` | المسؤول الذي طلب النشر |

استخدم قفلًا أو معاملة في مشروعك لمنع ضغطتين متزامنتين من إنشاء محاولتين مقصودتين دون قصد. لا تُعد بناء محتوى المحاولة من بيانات إعلان تغيرت بعد POST؛ احتفظ بنفس المحتوى والمفتاح حتى تتضح النتيجة.

الخدمة تخزن إيصالاتها محليًا، لكنها لا توفر مسارًا لعرض كل إيصالات مشروعك؛ اعرض قائمة «آخر عمليات النشر» من سجل مشروعك.

## إعادة النشر

إذا كان هناك سجل `sent` سابق، اعرض تنبيه «تم نشر هذا العنصر سابقًا» واطلب تأكيد إعادة النشر. بعد التأكيد أنشئ UUID جديدًا وسجلًا جديدًا، مع الاحتفاظ بالسجل السابق. المفتاح الجديد يعني أن المستخدم يقصد منشورًا آخر.

إذا كانت محاولة سابقة `pending` فانتظرها. إذا كانت `unknown`، افحص القناة أولًا واتبع آلية الإغلاق الموضحة في [API](API.md). لا تحوّل إعادة المحاولة بعد خطأ اتصال إلى منشور جديد تلقائيًا.

## أمثلة العملاء

`examples/node-client.mjs` و`examples/php-client.php` يقرآن قائمة القنوات فقط عند تشغيلهما، ويحتويان أمثلة مكتوبة لاستدعاءات النشر. لا ينشران تلقائيًا.

```js
const payload = {
  key: savedAttempt.publication_key,
  target: savedAttempt.channel_id,
  text: savedAttempt.text,
  image: savedAttempt.image, // null أو { mime, data }
};
const accepted = await publisher.publish(payload);
// لا تعتبر accepted.status === "pending" نجاح نشر.
const receipt = await publisher.receipt(payload.key);
```

يمكن استخدام العملاء مع Express أو Laravel أو PHP مباشر أو أي باك إند آخر. يمكن لأي لغة أخرى استدعاء HTTP نفسه. ملفات PHP تعمل دون Composer؛ عدّل مسار require ليناسب مشروعك.
